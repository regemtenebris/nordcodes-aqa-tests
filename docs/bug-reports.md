# Баг-репорты

Дефекты, найденные при тестировании `internal-0.0.1-SNAPSHOT.jar`.
Каждый дефект воспроизводится автотестом с тегом `known-bug` и заведён как GitHub Issue
(ссылки на Issue есть в Allure-отчёте у соответствующих тестов).

Общие предусловия: приложение запущено с `-Dsecret=qazWSXedc -Dmock=<адрес заглушки>`,
все запросы содержат заголовки `Content-Type: application/x-www-form-urlencoded`,
`Accept: application/json`, `X-Api-Key: qazWSXedc`. Внешний сервис по умолчанию отвечает `200`.

---

## BUG-1. Токены с буквами G–Z отклоняются, хотя документация их допускает

**Серьёзность:** Major  **Приоритет:** High
**Автотест:** `TokenValidationTest.tokenWithAnyLatinLetterIsAccepted`

**Шаги:**
1. Отправить `POST /endpoint` с телом `token=ZZZZZZZZZZZZZZZZZZZZZZZZZZZZZZZZ&action=LOGIN`

**Ожидаемый результат:** `200 {"result":"OK"}` — по документации токен состоит из символов `A-Z0-9`.

**Фактический результат:** `400 {"result":"ERROR","message":"token: must match \"^[0-9A-F]{32}$\""}`

**Комментарий:** валидация допускает только шестнадцатеричные символы. Нужно выяснить, что верно —
документация или код, и привести их к единому виду.

---

## BUG-2. Ответ 3xx от внешнего сервиса считается успехом

**Серьёзность:** Major (безопасность)  **Приоритет:** High
**Автотесты:** `ExternalServiceResponseTest.redirectFromAuthIsNotSuccess`, `redirectFromDoActionIsNotSuccess`

**Шаги:**
1. Настроить внешний сервис: `POST /auth` отвечает `302`
2. Отправить `token=<валидный>&action=LOGIN`
3. Отправить `token=<тот же>&action=ACTION`

**Ожидаемый результат:** шаг 2 — `result: ERROR`, сессия не создаётся; шаг 3 — `403`.

**Фактический результат:** шаг 2 — `200 {"result":"OK"}`, сессия создана; шаг 3 — `200 OK`.

**Комментарий:** перенаправление не подтверждает аутентификацию. Если внешний сервис, например,
перенаправит на страницу входа, пользователь получит доступ без проверки. Аналогично для `/doAction`.

---

## BUG-3. Сбой внешнего сервиса возвращается как 500 Internal Server Error

**Серьёзность:** Minor  **Приоритет:** Low
**Автотест:** `ExternalServiceResponseTest.externalFailureIsReportedAsBadGateway`

**Шаги:**
1. Настроить внешний сервис: `POST /auth` отвечает `500` (или недоступен)
2. Отправить `token=<валидный>&action=LOGIN`

**Ожидаемый результат:** `502 Bad Gateway`, сообщение, указывающее на ошибку внешнего сервиса.

**Фактический результат:** `500 {"result":"ERROR","message":"Internal Server Error"}`

**Комментарий:** документация этот случай не описывает, ожидание основано на RFC 9110.
Сейчас невозможно отличить сбой самого приложения от сбоя внешней системы.

---

## BUG-4. Некорректные HTTP-запросы приводят к 500 Internal Server Error

**Серьёзность:** Minor  **Приоритет:** Low
**Автотесты:** `ProtocolTest.*`

| Запрос | Ожидаемо | Фактически |
|---|---|---|
| `GET /endpoint?token=...&action=LOGIN` | `405 Method Not Allowed` | `500` |
| `POST /endpoint` с `Content-Type: application/json` | `415 Unsupported Media Type` | `500` |
| `POST /unknown` | `404 Not Found` | `500` |

**Комментарий:** клиенту непонятно, что он сделал не так; ошибки клиента маскируются под ошибки сервера
и искажают мониторинг (рост 5xx).
