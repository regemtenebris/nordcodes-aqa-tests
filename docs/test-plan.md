# Тест-план: сервис `/endpoint`

Документ составлен по итогам исследовательского (exploratory) тестирования до написания автотестов.
Каждый пункт ниже покрывается автотестом; ID пункта указывается в Allure (`@TmsLink`).

## 1. Объект тестирования

- `POST /endpoint`, `application/x-www-form-urlencoded`, параметры `token`, `action`
- Авторизация: заголовок `X-Api-Key`
- Внешний сервис (мок WireMock): `POST /auth`, `POST /doAction`, тело `token=...`

## 2. Фактическое поведение (наблюдения)

| Ситуация | HTTP | Тело |
|---|---|---|
| Успех | 200 | `{"result":"OK"}` |
| Нет / неверный `X-Api-Key` | 401 | `Missing or invalid API Key` |
| Невалидный `token` | 400 | `token: must match "^[0-9A-F]{32}$"` |
| Нет `token` | 400 | `token: must not be null` |
| Невалидный / отсутствующий `action` | 400 | `action: invalid action '...'. Allowed: LOGIN, LOGOUT, ACTION` |
| Повторный LOGIN | 409 | `Token '...' already exists` |
| ACTION / LOGOUT без LOGIN | 403 | `Token '...' not found` |
| Внешний сервис ответил не 2xx/3xx или недоступен | 500 | `Internal Server Error` |

## 3. Чек-лист проверок

### LOGIN
- [x] L-1 Успешный LOGIN: 200 OK, ровно один запрос на `/auth` с корректными заголовками и телом
- [x] L-2 Повторный LOGIN того же токена: 409, повторного запроса на `/auth` нет
- [x] L-3 `/auth` отвечает ошибкой (400/401/403/404/500/503): ERROR, токен не сохраняется
- [x] L-4 `/auth` недоступен / таймаут: ERROR, токен не сохраняется
- [x] L-5 После неуспешного LOGIN повторный LOGIN возможен
- [x] L-6 При LOGIN не вызывается `/doAction`

### ACTION
- [x] A-1 ACTION после LOGIN: 200 OK, запрос на `/doAction` с корректными заголовками и телом
- [x] A-2 ACTION без LOGIN: 403, `/doAction` не вызывается
- [x] A-3 ACTION после LOGOUT: 403
- [x] A-4 ACTION можно выполнить многократно
- [x] A-5 `/doAction` отвечает ошибкой: ERROR, сессия при этом не теряется
- [x] A-6 Токены изолированы: LOGIN токена A не даёт доступа токену B

### LOGOUT
- [x] O-1 LOGOUT после LOGIN: 200 OK, внешний сервис не вызывается
- [x] O-2 LOGOUT без LOGIN / повторный LOGOUT: 403
- [x] O-3 После LOGOUT возможен новый LOGIN
- [x] O-4 LOGOUT работает при недоступном внешнем сервисе

### Валидация `token` (классы эквивалентности и граничные значения)
- [x] V-1 Валидные: 32 цифры, 32 буквы, смешанный
- [x] V-2 Длина 31 / 33 / 0 / 1 / 64
- [x] V-3 Строчные буквы, спецсимволы, пробелы, кириллица
- [x] V-4 Параметр отсутствует
- [x] V-5 Буквы G–Z (по документации A-Z допустимы)
- [x] V-6 При невалидном токене внешний сервис не вызывается

### Валидация `action`
- [x] V-7 Неизвестное значение, нижний регистр, пустое значение, параметр отсутствует

### Безопасность (API-ключ)
- [x] S-1 Без заголовка / пустой / неверный / в другом регистре: 401
- [x] S-2 При 401 внешний сервис не вызывается и токен не сохраняется

### Протокол
- [x] P-1 Неподдерживаемый метод (GET), Content-Type (JSON), несуществующий путь
- [x] P-2 Ответ всегда JSON с полем `result`; при ERROR присутствует `message`

### Конкурентность
- [x] C-1 Параллельные LOGIN одного токена: ровно один успех и ровно один вызов `/auth`

## 4. Найденные расхождения (кандидаты в баг-репорты)

| ID | Описание | Ожидание | Факт | Серьёзность |
|---|---|---|---|---|
| BUG-1 | Токен с буквами G–Z отклоняется | По документации алфавит `A-Z0-9` | 400, regex `^[0-9A-F]{32}$` | Major |
| BUG-2 | Ответ 3xx от внешнего сервиса считается успехом | Успех только при 2xx | LOGIN / ACTION = OK | Minor |
| BUG-3 | Ошибка внешнего сервиса отдаётся как 500 `Internal Server Error` | Осмысленное сообщение, код 502/503 | 500, общее сообщение | Minor |
| BUG-4 | GET / JSON-тело / несуществующий путь → 500 | 405 / 415 / 404 | 500 | Minor |
